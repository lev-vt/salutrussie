# ТЗ Codex: два интерактивных инструмента к гайду «Доходы иностранцев с 2027 года»

**Редакционная версия:** 2026-11-01; `draft_for_owner_review`. Это **спецификация юридической логики и UX**, а не работающий программный код и не разрешение развернуть инструмент. Реализация, безопасность, автоматические и ручные тесты принадлежат Codex.

1. [Официальный № 241-ФЗ](https://publication.pravo.gov.ru/document/0001202607260001), особенно ст. 1, пп. 1, 4, 6, 7, 8, 9, 10, 13; ст. 2 (вступление в силу/переходные положения).
2. [Статья 1 № 241-ФЗ в полном тексте](https://www.consultant.ru/document/cons_doc_LAW_540338/3d0cac60971a511280cbba229d9b6329c07731f7/).
3. [Статья 2 № 241-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_540338/b004fed0b70d0f223e4a81f8ad6cd92af90a7e3b/).
4. [115-ФЗ — действующая и будущие редакции](https://www.consultant.ru/document/cons_doc_LAW_37868/).
5. Акты субъектов РФ о ПМ и региональном коэффициенте, а также официальный показатель Росстата для ограничения порога — **отдельные обязательные источники каждого числового параметра**. Ни один региональный набор данных в текущем пакете не утверждён.
6. Действующие [Правила № 21](https://base.garant.ru/12151545/) и [проект МВД от 15.07.2026](https://mvdmedia.ru/news/official/mvd-rossii-razrabotan-proekt-postanovleniya-pravitelstva-rossiyskoy-federatsii-o-vnesenii-izmeneniy-/) не смешивать.

## 1. Необходимая архитектура: два разных инструмента

**A. Проверка применимости:** дерево решения определяет, **может ли** новый подп. 8 п. 1 ст. 7/9 быть применим к заявителю. Не делаем расчёт в ветке `POTENTIAL_EXCEPTION`.

**B. Калькулятор ориентировочного порога:** вычисляет **числовой норматив** только при юридически однозначном режиме и подтверждённых официальных данных. НИКОГДА не обещает, что достигнуты условия, не даёт заключение о законности пребывания и не подменяет факт деятельности.

Порядок интерфейса: сначала проверка применимости → затем по выбору калькулятор; допускается открыть калькулятор отдельно с жёстким предупреждением и всеми обязательными полями. Не сохранять в браузере паспорта, даты рождения, адреса и иные персональные данные; это не нужны для задач.

## 3. Выходы проверки применимости (не бинарное «да/нет»)

- `NOT_YET_EFFECTIVE`: дата до 01.01.2027; текст «Новые подпункты о деятельности и доходах для РВП/ВНЖ ещё не вступили в силу на выбранную дату; существующие обязанности продолжают действовать».
- `OUT_OF_SCOPE`: патент/разрешение на работу/иной режим; текст «Для этого статуса действует другая процедура. Не используйте расчёт для РВП/ВНЖ как заключение по своему случаю».
- `POTENTIAL_EXCEPTION`: закон предусматривает исключение по подтверждённо указанному основанию; «Возможное исключение из конкретного основания отказа/аннулирования. Подтвердите документами; ежегодные уведомления и другие обязанности сохраняются».
- `POTENTIALLY_APPLIES`: указанных исключений не найдено и статус определён, но требуется проверить деятельность/периоды; «Новые требования потенциально применимы».
- `NEEDS_LEGAL_REVIEW`: неизвестный статус, сомнительные данные, NPD-only, passive-only, неоднозначный переходный период, конфликт ответов, ВНЖ после 702 или отсутствие признаков квалифицированного исключения при неопределённых документах.

Обязательно выводить массив `reason_codes[]`, массив `legal_sources[]`, `verification_date`, `target_date`, `disclaimer` и CTA.

Приоритет дерева:

1. Если статус не РВП и не ВНЖ → `OUT_OF_SCOPE` (без вывода «требования не касаются»).
2. Если дата раньше вступления нужной нормы → `NOT_YET_EFFECTIVE`, но можно включить отдельный раздел «что меняется в будущем».
3. Если явно не хватает статуса, основания, юридической квалификации → `NEEDS_LEGAL_REVIEW`.
4. Применить перечни **отдельно**:
   - для РВП: очное обучение в определённых российских организациях, пенсионер, признанная нетрудоспособность и определённые дети, зависимый несовершеннолетний/недееспособный от родителя-гражданина РФ, лица с РВП по 702, лица по признанию представляющими интерес для РФ, граждане Беларуси и предусмотренные члены семьи;
   - для ВНЖ: аналогичный ряд образования, пенсии, нетрудоспособности, иждивения и Беларуси; лицо с ВНЖ в связи с признанием представляющим интерес РФ; **НО НЕ** общий флаг «ВНЖ ранее было РВП по 702».
5. При подтверждённом в ответах исключении → `POTENTIAL_EXCEPTION`, обязательно без автоматического юридического заключения.
6. Если `NPD`, `PASSIVE_ONLY` или `MIXED` с сомнительным видом деятельности → `NEEDS_LEGAL_REVIEW`, даже при возможности достаточного дохода.
7. Если `job_change_within_report_period=YES` или `HONORS_GRADUATE_VNZH` → показать соответствующую спецзащиту **на проверку**, не считать автоматически выполненной.
8. В остальных определённых случаях → `POTENTIALLY_APPLIES`.

Недопустимо заключать, что человек «подлежит аннулированию»: решение всегда зависит от проверок, времени, доказательств и процедуры.

## 4. Числовая модель калькулятора

### 4.1. Источники региональных данных

Структура `RegionLegalParameters`:

```text
region_code             string, официальный код
year                    integer
pm_per_capita_rub       decimal, >0
pm_law_url              official HTTPS, не пустой
pm_act_number           string
coefficient_raw         decimal | null
coefficient_law_url     official HTTPS | null
coefficient_status      OFFICIAL_VALUE | OFFICIALLY_NOT_SET | UNVERIFIED
average_wage_cap_rub    decimal, >0
average_wage_year       integer
average_wage_source_url official HTTPS
source_checked_at       ISO date
legal_version           string
review_status           VERIFIED | DRAFT | EXPIRED
```

Правило отсутствия коэффициента: `effective_coefficient=1` **только** если для данного года подтверждено, что законом субъекта он не установлен (`OFFICIALLY_NOT_SET`) либо официально установлен ниже 1. `null` с `UNVERIFIED` **не** означает 1.

**Не подставлять значения ПМ за 2026 год вместо 2027. Не использовать вымышленные средние зарплаты.** Статистический потолок должен быть взят за предусмотренный законом наиболее поздний доступный календарный год из официальных сведений.

### 4.2. Символическая формула — при подтверждённых данных

Для одного субъекта и года:

```K_effective = max(1, K_official)  // или 1 при официально подтверждённом отсутствии K
BaseRegion = min(PM_per_capita * K_effective, average_wage_cap)
Persons = 1 + number_of_qualifying_dependents_in_Russia
MonthlyThreshold = BaseRegion * Persons
```

Для работы в нескольких регионах: **взять максимум** из рассчитанных применимых `BaseRegion`, затем умножить на `Persons`.

```BaseMultiRegion = max(BaseRegion(region_1), ..., BaseRegion(region_n))
MonthlyThreshold = BaseMultiRegion * Persons
```

Закон использует формулировки «в среднем за месяц отчётного периода» для РВП/ВНЖ. **НЕ выводить** универсальное умножение на 12 как юридическое обязательство для всякой ситуации. Можно дополнительно показывать `Full12MonthIllustration=MonthlyThreshold*12` только при подтверждённом полном 12-месячном периоде и подписи «арифметический ориентир, не проверка соблюдения нормы». Для периода работы после смены работодателя либо специальных выпускников действует отдельная правовая оценка: **не вычислять** автоматическую достаточность.

Денежные вычисления хранить как decimal/целые копейки, не как IEEE float для юридических значений. Показывать 2 знака после запятой, округление до копейки вверх при формировании минимального рублёвого порога, документировать решение. Числовой диапазон: зависимых людей не более 30 в интерфейсе; если больше — `NEEDS_LEGAL_REVIEW`, а не отказ по закону.

### 4.3. Что можно и чего нельзя считать

**Можно при полном наборе данных:** условный месячный норматив, его исходные параметры, количество лиц, сравнение нескольких регионов и ссылку на источник.

**Нельзя автоматически обещать:** «у вас достаточно заработка», «ВНЖ не аннулируют», «можно не работать, если вклад крупный», «фиктивное трудоустройство на один день», «любой доход на иностранном счёте засчитывается». Не складывать за один период зарплату с дивидендами другого периода как однородные величины.

Если пользователь вводит зарплату, показывать её только как **непроверенную пользователем сумму** рядом с нормативом, без статуса «соответствует». По умолчанию поле фактического дохода **не требуется** — это инструмент нормативного порога, а не калькулятор налоговой декларации.

### 4.4. Расчёт не выполняется, когда

- Отсутствуют `VERIFIED` региональные значения хотя бы по одному выбранному региону.
- Нет официального источника регионального ПМ, коэффициента (или доказанного отсутствия), статистического ограничения.
- Неизвестно количество иждивенцев или регион(ы) деятельности.
- Для категории действует отдельный механизм (патент, специальное разрешение).
- Юридическая квалификация деятельности/регионов неясна.
- Нормы для выбранной даты ещё не действуют (можно показать «предварительный ориентир 2027» при полном наборе будущих данных, явно как будущее правило).
- Период работы / переход 2026–2027 требует специальных правил для вывода об общей годовой сумме.

## 5. Пользовательские тексты

- Заголовок: **«Кого затронут новые требования?»**
- Пояснение: «Начните с вашего миграционного статуса: требования к РВП, ВНЖ и патенту различаются».
- Заголовок второго инструмента: **«Какой ориентировочный доход требуется?»**
- Поле: «Сколько человек в России находятся на вашем иждивении? Не считайте себя: мы добавим вас автоматически».
- Уточнение: «Считаются не все родственники, а только лица, соответствующие условиям закона».
- Недоступность данных: **«Точный расчёт пока недоступен: официальные показатели для выбранного региона и года не подтверждены. Мы не подставляем приблизительные значения».**
- Результат: «Ориентировочный месячный порог: [СУММА] ₽, на [N] человек. Основание: [акт субъекта], [коэффициент], [официальная статистика], проверено [дата]».
- Дисклеймер: «Это справочный норматив, а не подтверждение вашего дохода и не гарантия сохранения РВП/ВНЖ».
- CTA: «Нужна проверка конкретного случая? Получите юридический анализ с учётом ваших документов».

## 6. Технические требования / безопасность

- Версионируемый, ревьюируемый офлайн JSON нормативных параметров; **не** загружать региональные числа из неподписанных источников при клиентском просмотре.
- Unit-тесты формул, состояний применимости, переходных дат, исключений, ошибок данных; сценарии ниже в `calculator_tests.json`.
- Все ссылки на актуальные источники открываются; источник и дата видны в интерфейсе; юридические тексты снабжены версией.
- Только обработка в браузере без сервера для этих простых полей, без отправки вводимых параметров в аналитику и без cookies.
- Доступность клавиатуры, мобильный экран и озвучивание ошибок; без цветового-only кодирования юридического статуса.
- Codex сначала создаёт staging с disabled feature flag для числового блока; включает после подтверждения нормативной таблицы и тестов.
- На каждом изменении 115-ФЗ, актов субъектов, статистики и периода — юридическая ревизия и новый checksum данных.
- Не изменять main или production без согласования.

## 7. Definition of Done

- [ ] Подтверждён актуальный закон на день выпуска и дата действия каждой ветки дерева.
- [ ] Проверены все исключения по РВП и ВНЖ отдельно.
- [ ] Проверены официальные параметры (ПМ, К, статистический потолок) по каждой доступной паре регион/год.
- [ ] Unit, property и ручные тесты пройдены; ошибки блокируют числа.
- [ ] Различаются работа и доход, доходы разных календарных периодов.
- [ ] На интерфейсе видно, почему расчёт не выполнен.
- [ ] Независимый юридический аудит и одобрение владельца.
- [ ] Никакой production-публикации без отдельного разрешения.
