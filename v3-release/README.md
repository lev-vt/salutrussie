# SalutRussie V3.2 — подготовка к запуску

Тестовый сайт сохраняет noindex,nofollow. Не размещать карту сайта тестовой версии в поисковых консолях. Корневой robots.txt предыдущей версии не изменён.

1. Подтвердить домен и название бренда, выписку ЕГРЮЛ, оферту, политику данных, фактический хостинг, каналы связи и необходимость GDPR. Проверить содержание, ссылки и адаптивность на реальных устройствах.
2. Подготовить отдельную локальную копию из каталога v3: `python3 v3-release/prepare_seo.py --source v3 --output release-review --site-url https://CONFIRMED-DOMAIN/`. Скрипт оставляет noindex и добавляет canonical, hreflang и og:url. Никакой публикации не производится.
3. Только после отдельного утверждения создать чистую релизную копию с параметром --enable-indexing. Скрипт создаст sitemap.xml и robots.txt, исключит служебные страницы, сохраняя само соответствие языков.
4. Проверить итоговые URL, ответы HTTP, перенаправления, мобильную доступность, разметку Article, фактические Core Web Vitals. Настроить Google Search Console и Яндекс Вебмастер после верификации домена. Не обещать индексацию или появление в генеративных ответах.

Ни цены, ни действующий платёжный шлюз не включаются. Не добавлять неподтверждённые отзывы, рейтинги, адреса, авторство, гарантии или машинные страницы ради запросов.

## Локальная проверка релиза

После сборки закрытой копии выполнить `python3 v3-release/validate_release.py --root release-review --site-url https://CONFIRMED-DOMAIN/`. Для отдельно утверждённой индексируемой копии добавить `--indexable` и указать её каталог. Проверяются 162 языковые страницы и корневая страница: canonical, hreflang, robots meta, локальные ссылки и ресурсы, JSON-LD и соответствие sitemap. При ошибках код завершения ненулевой. Скрипт не обращается к сети, не публикует сайт и не заменяет браузерную проверку.

## Кеширование и публикация на REG.RU

`prepare_seo.py` теперь добавляет к локальным CSS, JS и favicon параметр `v` из первых 12 символов SHA-256 содержимого файла. При изменении файла меняется его URL на всех страницах. Существующие ручные параметры `v` заменяются; остальные параметры URL сохраняются. `validate_release.py` проверяет соответствие каждого параметра реальному файлу. HTML по-прежнему остаётся `noindex,nofollow`, пока явно не указан `--enable-indexing`.

Перед заменой файлов сохраните копию **фактического** каталога сайта на REG.RU вне публичного `/www/salutrussie.ru/`. Локальная копия, собранная из GitHub, не заменяет серверную резервную копию. В корень сайта распаковывайте содержимое релизного архива (`assets/`, `ru/`, `en/`, `fr/`, `index.html`, `robots.txt`), а не вложенную папку или сам ZIP. Коммит в `gh-pages` сам по себе не разворачивает файлы на REG.RU.

Для текущего сайта запросите в настройках хостинга REG.RU или у его поддержки правило для **всех HTML-ответов** (включая `/`, `/ru/`, `/en/`, `/fr/` и вложенные адреса): `Cache-Control: no-cache, must-revalidate`. Оно разрешает повторное использование HTML только после проверки свежести у сервера. Сохраняйте ETag/Last-Modified. Для версионированных CSS, JS и favicon можно оставить текущий долгий срок кеширования. Не устанавливайте `no-store` для всего сайта и не меняйте параметры почты, DNS-записи MX/TXT, сертификат или SSL-настройки ради этого правила. Поскольку наблюдаемый веб-сервер отвечает как nginx, не рассчитывайте, что `.htaccess` изменит эти ответы без подтверждения REG.RU.

После загрузки проверьте обычным обновлением страницу в Safari, новый `?v=` в исходном HTML, заголовок HTML и ответы 200 для новых URL ресурсов. Настройка 301 для HTTP и `www` на `https://salutrussie.ru/` — отдельное правило только для веб-трафика; проверьте его после внесения. Индексацию, sitemap и регистрацию в поисковых консолях выполняйте отдельным решением после технической проверки.
