# Публикация SalutRussie

Сайт собирается в обычные статические HTML, CSS, JavaScript, шрифты и изображения. Серверная часть, база данных и переменные окружения на хостинге не нужны. Домен и хостинг подключает владелец.

Перед публичным размещением владелец подтверждает оператора персональных данных и утверждает политику обработки с учётом фактического хостинга, серверных журналов и каналов связи. Текущий `/ru/privacy/` и `/fr/privacy/` описывают только работу контактных кнопок; они не являются политикой обработки персональных данных и исключены из sitemap. Десять новых юридических статей также требуют окончательного просмотра практикующим юристом: исходный редакционный пакет помечен `revised_pending_lawyer_approval`. Эти согласования не мешают просматривать и технически собирать сайт, но нужны до его открытия клиентам.

Для передачи без Git-репозитория подготовлен `build/packages/salutrussie-owner-build-kit-NOT-FOR-UPLOAD.zip`. Он содержит исходники сборки, десять отредактированных публикаций и закрытую от индексации версию `dist/` для просмотра. После извлечения архива выполните команды ниже **из его корня**. Не загружайте этот комплект целиком на хостинг: там есть исходный код и черновая сборка. Для хостинга предназначен только создаваемый им `salutrussie-publication.zip`.

## 1. Подготовить окончательный архив

Для генерации публичного архива нужен **точный подтверждённый адрес** сайта: с `https://`, выбранным вариантом `www` или без него и без пути. Этот адрес попадёт в canonical, hreflang, sitemap и структурированные данные. Адрес почты не подтверждает адрес сайта.

В каталоге проекта, где находится `package_release.py`, выполните:

```bash
python3 -B -m unittest discover -s tests -v
python3 -B package_release.py --origin https://ВАШ-ПОДТВЕРЖДЁННЫЙ-ДОМЕН
```

Нужен Python 3.11 или новее; сторонние пакеты не устанавливаются. Скрипт пересобирает сайт в `build/release-check/`, запускает `verify_release.py`, проверяет файлы и создаёт:

- `build/packages/salutrussie-publication.zip` — содержимое корня сайта, готовое к загрузке;
- `build/packages/salutrussie-publication.sha256` — контрольная сумма;
- `build/release-check/` — те же распакованные файлы.

Если проверка обнаружит ошибку, архив не считается готовым. Исправьте причину и повторите команду. Не публикуйте архив для просмотра `salutrussie-preview-NOT-FOR-PUBLICATION.zip`: в нём намеренно выставлен `noindex`.

Для повторной подготовки комплекта владельца из рабочего репозитория используется `python3 -B package_release.py --kit`. Скрипт проверяет, что комплект можно распаковать и пересобрать отдельно от репозитория.

## 2. Требования к хостингу

- Статический веб-хостинг с HTTPS и сертификатом для выбранного адреса.
- Корень сайта должен соответствовать **содержимому** архива: `index.html`, `ru/`, `fr/`, `en/`, `assets/`, `robots.txt`, `sitemap.xml` находятся непосредственно в корне сайта.
- Сервер должен обслуживать `index.html` для адресов каталогов с завершающим `/`, например `/ru/knowledge/articles/rvp-shared-values-702/`. Редирект с адреса без завершающего `/` на адрес с `/` полезен, если хостинг его поддерживает.
- Отдача статических файлов с корректными типами: `text/html`, `text/css`, `text/javascript` или `application/javascript`, `image/svg+xml`, `font/woff2`, `application/xml` для sitemap.
- Страница `404.html` может быть назначена обработчиком ошибки 404, если хостинг это позволяет. При этом не нужно превращать все неизвестные адреса в ответ `200`.
- Выбранный вариант адреса (`www` или без него) должен быть основным; альтернативный вариант и HTTP перенаправляются на него постоянным редиректом. Настройка DNS и редиректов зависит от провайдера.

Не загружайте на публичный сервер исходный ZIP со статьями, `src/`, `docs/`, `tests/`, `.git/`, исходные `.py`-файлы или архив для просмотра. Публичный ZIP формируется только из проверенной сборки.

## 3. Загрузить и проверить

1. Сверьте SHA-256 ZIP с содержимым файла `.sha256` (на macOS: `shasum -a 256 build/packages/salutrussie-publication.zip`).
2. Распакуйте архив в **корневую папку сайта** на хостинге или используйте функцию загрузки ZIP с извлечением в корень. Не создавайте лишнюю папку `salutrussie-publication/` перед файлами.
3. Откройте по HTTPS главную страницу, `/ru/`, `/fr/`, `/en/for-business/`, раздел услуг и экспертных статей. Проверьте меню, язык, оглавление длинной статьи и контактные ссылки на телефоне и компьютере.
4. Откройте `/robots.txt` и `/sitemap.xml`: оба должны отвечать `200`; адреса в sitemap должны использовать выбранный домен. Проверьте canonical и `hreflang` в исходном HTML нескольких страниц.
5. Убедитесь, что изображения, CSS, JavaScript и шрифты загрузились без ответов `404`, а неизвестный адрес даёт страницу ошибки и HTTP `404`.
6. Проверьте контактные действия в реальном браузере: открытие почтового клиента, Telegram или WhatsApp. Сайт не отправляет формы и не хранит сообщения.

Изменение домена после сборки требует повторной команды `package_release.py --origin …` и повторной загрузки архива. Не редактируйте готовые HTML вручную: иначе canonical, sitemap и разметка могут разойтись.
