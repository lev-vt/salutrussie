# Автовозобновление — исправление и фактическая проверка

## Результат

Безопасный запуск Codex через самостоятельный пользовательский launchd **проверен**.
Расписание было включено только после успешного одноразового теста, затем само
остановилось по завершении аудита и фиксации вопросов для владельца.
Сейчас повторяющихся заданий SalutRussie нет. Это штатная остановка, не ошибка.

## Точная причина прежнего отказа

В старом plist весь Python-супервизор запускался через sandbox-exec. Уже из этого
процесса safety_gate вызывал codex sandbox, то есть пытался применить второй
Seatbelt. Воспроизведение на безвредном /usr/bin/true показало:

- один sandbox-exec: exit 0;
- sandbox-exec внутри sandbox-exec: exit 71, sandbox_apply: Operation not permitted.

См. `launchd-check/seatbelt-reproduction.json`. Это воспроизводит конкретный
конфликт вложения на этом Mac; не утверждается, что любые вложенные политики
macOS всегда ведут себя одинаково.

## Исправленная граница безопасности

launchd запускает **фиксированный доверенный Python-host** напрямую, с обычными
правами пользователя. Host не является свободным AI-агентом: он выполняет только
заданные Python-этапы, сохраняет JSON и не исполняет команды/скрипты из ответов
моделей или полученного архива. Сам host не объявляется OS-изолированным.

Все модельные процессы по-прежнему запускаются существующим CodexClient через
его отдельный внешний Seatbelt и явный `--sandbox read-only`, с игнорированием
глобального config и правил. Shell, браузер, плагины, hooks и инструменты записи
у рабочих ролей отключены. Python-host пишет результаты; AI возвращает данные.
Нативный тест командной песочницы выполняется host отдельно, до модели, без
лишней внешней обёртки host. Таким образом, ограничения модельных операций
сохранены, а некорректное вложение устранено архитектурно.

Не использовались sudo, yolo, danger-full-access, изменение глобального Codex
config или отключение системной защиты.

## Реальный тест

`launchd_probe.py` зарегистрирован одноразовым заданием без интервала.
`launchd-check/process.json` подтверждает parent_pid=1: запуск сделан launchd,
а не subprocess интерактивной сессии.

Прошли нативные проверки чтения, запрета записи/перезаписи и shell-сети.
Отдельная реальная модельная сессия попыталась создать только тестовый файл;
CLI-router отказал: writing is blocked by read-only sandbox. Файл не появился.
Доказательства: `launchd-check/acceptance.json`, `safety-check.json`,
`actual-sandbox-check.json`, `00_sandbox_probe/stderr.txt` и JSONL.

После этого зарегистрирован исправленный runner с интервалом 1800 секунд,
RunAtLoad и отдельным ограничителем срока на 8 часов. Реально выполнен старт
RunAtLoad. Отдельного ожидания следующего 30-минутного тика не проводилось.
Сам worker также наблюдался с PPID 1. Повторный запуск во время его работы
вернул duplicate_skipped; запись есть в `night/journal.jsonl`.

## Восстановление, пределы и остановка

- flock не позволяет двум worker работать одновременно; ядро освобождает lock
  при смерти процесса.
- Checkpoint записывается атомарно после каждого этапа. Завершённый ответ Codex
  восстанавливается по result SHA-256, даже если host не успел обновить индекс.
- Имитация остановки проверена как исключением, так и реальной смертью отдельного
  тестового процесса (exit 75) с последующим новым процессом: завершённый этап
  не выполнялся повторно.
- Usage-limit ошибки дают ожидание 30/60/120 минут, без busy loop. Постоянные
  ошибки останавливаются после трёх попыток; максимум 12 модельных попыток.
- Максимум 8 часов; время проверяется host перед этапами, CLI получает ограниченный
  timeout. Отдельное expiry-задание прекращает worker и его модельные процессы.
- Полный восьмичасовой прогон и настоящее исчерпание лимита Plus не моделировались
  расходованием квоты: проверены тестовые часы/ошибки и реальный безопасный старт.
- Завершённые этапы аудита нельзя перезапустить простой повторной установкой.
- Простая остановка: `python3 -B night_resume.py stop`. Состояние и журналы остаются.

Текущий аудит дошёл до needs_owner_decision; runner и expiry сами выгрузились.
Одноразовый probe также выгружен после проверки. Отсутствие всех трёх заданий
проверено: `launchd-check/auto-stop-verification.json`.

## Фактическая работа команды

5 модельных вызовов, 5 разных session ID: SandboxProbe ×1, Manager ×2,
Website QA ×1, Reviewer ×1. Все вызовы read-only. Счётчики: 89012 входных токенов,
включая 7936 кэшированных, и 2197 выходных. API-ключи и покупка кредитов не нужны.
См. `launchd-check/final-verification.json`.

22 автоматических теста проходят, включая все прежние 15. История неуспешного
первого варианта сохранена в `night-history-*`, не удалена.

Mac должен быть включён, не спать, иметь активную пользовательскую сессию,
интернет и действующую ChatGPT-авторизацию. Приложение ChatGPT для этого CLI-host
может не быть открыто; вход в macOS и доступ к авторизации всё равно необходимы.
Автоматического пробуждения/восстановления после перезагрузки не настраивали.
